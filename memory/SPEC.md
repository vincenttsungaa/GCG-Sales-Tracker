# Gundam Collection Tracker — Spec

Personal Gundam Card Game inventory & sales tracker. Single user, **no auth**.

## What it does
- **Unified inventory** of cards (`kind="card"`) and general items (`kind="item"`) with a sale lifecycle: `for_sale → pending → sold`.
- **Tabs**: All Items (active, non-sold) / For Sale / Pending / **Sold** (= sold items, auto-moved on sale; Restore puts them back to `for_sale` and clears the deal record). The Sold tab's internal id is still `archive` (`TabId` in `frontend/src/lib/types.ts`).
- **Deal record**: buyer name, deal date (YYYY-MM-DD), sale price (AUD, **per unit**). Required by the backend when marking `sold` (422 otherwise); optional when marking `pending`.
- **Profit tracking**: optional `purchase_price` (AUD, per unit) per entry; sold records show total profit `(sale_price − purchase_price) × qty` (green/red, grid + table + Sold tab); Realized Sales stat shows profit after costs.
- **Partial sales**: deal dialog has "Qty to sell" (1..quantity) for multi-qty entries; selling fewer creates a standalone sold record (shown on the Sold tab) and keeps the listing active with reduced qty and cleared deal fields; selling all = whole-entry sale. `quantity_sold` > owned → 422.
- **Photos**: optional `image_url` per entry; grid view renders a thumbnail (hidden if the URL fails to load).
- **Filters** (client-side, instant, combinable): name search, color, type, rarity, buyer name, deal-date from/to. Color pills + type/rarity selects + buyer text + date range in FilterBar. Filter state/helpers live in `frontend/src/lib/filters.ts`. The **Buyer** filter only shows on the Pending and Sold tabs; switching to any other tab clears it.
- **Stats strip** (`StatsStrip.tsx`): Collection Value A$ (active items at list price), Realized Sales A$ (profit after costs · sold count), Cards & Items (total QTY of active entries, split into cards · items). Sold entries are excluded from Cards & Items.
- **Views**: tile grid (default; `ItemCard.tsx`) + responsive list toggle (`ItemTable.tsx`). The list renders a dense table at ≥1024px and stacked touch-friendly rows below that (2 columns from 768px), switching via `lib/useMediaQuery.ts` so only one layout is mounted (test ids stay unique). Both layouts show every field: photo, name, condition, notes, kind, color, type/category, rarity, price (sold total + list/unit + profit), qty, status, buyer + deal date, and all actions. Sonner toasts confirm every mutation.
- **Pagination** (`components/Pagination.tsx`, client-side): 10 entries per page (`PAGE_SIZE` in `Dashboard.tsx`) in both table and grid views, with Prev/Next and page numbers ("Showing 11–20 of 23"). Controls only appear when there is more than one page. Resets to page 1 when the tab or filters change; steps back a page if the last page empties. Tab counts and the stats strip still count every entry, not just the current page.
- **Card database** (`backend/lib/card_catalog.py`, `routers/cards.py`, `scrape_cards.py`): scrapes https://www.gundam-gcg.com/en/cards/ — every package from GD01 to Promotion card, including parallel `_pN` printings — into `backend/data/cards.json` (id, card_no, name, color, card_type, rarity, set_code, set_name, product, level/cost/ap/hp/trait) and `backend/data/card_images/<id>.webp` (gitignored). Refresh with `python scrape_cards.py` or POST `/api/cards/sync` (the "Update" link in Add Card). Site rarities are normalised (`LR +` → `LR+`), types lowercased (`UNIT・TOKEN` → `unit token`), color `-` → null. Tokens/resources/EX cards take their set code from the product they come in (`[ST13]`).
- **Add Card** (`AddCardDialog.tsx`): search the card database by name or number → pick the printing → set copies with the **− / + on the card image** (always visible; shown as e.g. `Qty GD01-001 (3x)` — there is no Qty box) and enter asking price, purchase price, notes (no condition) → added as For Sale with name/color/type/rarity/set/card_no/image copied from the catalog (`card_id` links back). "Enter the card manually" falls back to the old free-form form. Editing a catalog card only edits price/qty/condition/notes. **Add to bundle** puts the picked card into the shared bundle (see Bundles) instead of listing it; the dialog never scrolls sideways (`overflow-x-hidden`, footer wraps).
- **Tile grid** (default view, `ItemCard.tsx`): card-list style tiles — rarity chip + card number header, card image (63:88), name, then color · type · set, a quantity line `GD01-001 (3x)` (code + copies; PB card listings list each card, e.g. `GD02-110 (2x), ST05-010 (1x)`), asking/sold price, paid, profit, deal, notes, actions. The price box has **no Qty row** (and no gap for it) in the grid view; the list view still shows Qty. Bundles get an indigo chip and type `bundle` (header label blank, except product bundles that share one code show it, e.g. `ST13`); the table's Kind column shows `—` for bundles. Kit bundles show a collage of each ASSEMBLE kit's photo.
- **Hover previews** (`HoverZoom` in `InfoTip.tsx`): pointing at a card, kit, resource, alt-art or sleeve image (Add Card results + picked card, Add Item part/pick tiles, grid tiles) shows a larger copy, scaled to fit 270×380 and **never enlarged** past the image's own size.
- **Bundles**: several products and/or cards listed as one entry (`bundle_items`, each a `BundleEntry` with its own optional price/qty). Built from Add Item or Add Card — the bundle state lives in `Dashboard.tsx` and is shared, so you can switch between the two dialogs while building it (`BundleBar` in `AddItemDialog.tsx`). `bundleKind()` in `badges.tsx` classifies a bundle as `same` / `mixed` / `item-card`.
- **Product database** (`backend/lib/product_catalog.py`, `routers/products.py`): scrapes https://www.gundam-gcg.com/en/products/list.php?page=N (all pages, every category **except BOOSTER PACK**) into `backend/data/products.json` (id = page slug e.g. `pb01`, name, code e.g. `PB01`, category, release_date, msrp, url) and `backend/data/product_images/<id>.webp` (main images, **tracked in git** — `.gitignore` keeps `*.webp`/`*.jpg` there and ignores the generated part/mosaic SVGs; local replacements for the site photos are named `source-local_*.webp`). Refresh with `python scrape_cards.py --products-only` or POST `/api/products/sync` ("Update database" in Add Item). Untagged products count as `other`.
- **Add Item** (`AddItemDialog.tsx`): product names lead with their code — `[ST14] Heavy Dominion`, `[PB02] Premium Accessory Set …` (`code_first` in `models/item.py`, applied when scraping, when serving `/api/products`, and when reading items that came from the product database). Search the product database (name/code, category chips) → pick → asking price, purchase price, qty, notes → added as For Sale with name/category/code (`set_code`)/image copied (`product_id` links back). Products sold in more than one edition — read from the MSRP text, e.g. ST01–ST04 "Regular Version / Special Edition" — show an Edition picker (Regular Version by default); the choice is stored in `edition` and shown on the tile and list. **Sealed by default**: a product with nothing ticked or picked is listed as Sealed — there is no Sealed tile; a "Listed as Sealed (i)" line shows instead. Sleeves stay Sealed even with designs picked, and PB03 Sleeves alone count as Sealed. Starter decks ST05–ST14 offer **Brick** (a case of sealed decks) as a separate tile; ST01–ST04 Special Edition offers its GUNDAM ASSEMBLE kits. Brick or Sealed blocks **Extras** (the bonus pack counts as opened product — the note says to untick the whole product to list it). Once parts are picked, copies are set with − / + steppers and the Qty box is hidden; with nothing picked the Qty box shows. Text-only part tiles stack in one column next to image tiles. Premium Bandai sets show a **Part of the set** picker (`PRODUCT_OPTIONS` in `product_catalog.py`) stored in `part`: **PB01 / PB02** — Storage Box, Sleeves, Playmat, Deck Box, Separator, Resources, Alt-Art Cards ("Divider" was renamed Separator; old docs are migrated on read); **PB03** (1st Anniversary Set) — Storage Box, Sleeves (two designs, picked like cards), Playmat, Card Case, Damage Counter Dice, Resources (RP-068 standard/special), Alt-Art Cards and **EX Tokens** (split from Alt-Art by the `EX` card_no prefix). Physical-part listings use that part's photo as their image (`PART_PHOTOS`: crops of the official overview photos, and local transparent photos for the ST01–ST04 / PC01A / PC02A ASSEMBLE kits; served as `/api/product-images/<id>-part-<part>.svg`, cached in `data/product_images/`). Pick tiles for Resources / Alt-Art / EX Tokens / Sleeves show a picture (`PICK_TILE_IMAGES`). Picking **Resources**, **Alt-Art Cards** or **EX Tokens** shows a multi-select of those cards (images from the card database) stored in `resource_cards` / `alt_art_cards`; Edition Beta's Alt-Art list holds only its 12 `+` prints. Sleeve products show a design multi-select (`SLEEVE_DESIGNS`) stored in `sleeve_designs`; a design may carry its own `image` (`/cutouts/<pid>-<id>.webp`) used for the tile, the hover preview and single-design listings. Each picked card or design has **− / + copy buttons** over its centre (− at 1 unpicks it) and a `2x` badge; copies are stored in `card_quantities` and `quantity` is their total, listed as e.g. `GD02-110 (2x), ST05-010 (1x)`; editing keeps Qty locked to that total. The listing's image is that card when one is selected, or with several a picture of **only the selected cards** — e.g. `/api/product-images/<id>-resources.svg?cards=RP-025,RP-027`, an SVG mosaic (set order, √n columns) cached per selection in `data/product_images/`. Pre-made transparent cutouts live in `frontend/public/cutouts/*.webp`; `lib/cutout.ts` (`PREMADE`) maps `/api/product-images/<name>.(svg|webp)` to `/cutouts/<name>.webp`. "Enter the item manually" falls back to the free-form form. Both catalog dialogs share `CatalogSync.tsx` for the download/update control.
- **Manual Add/Edit dialog** (`ItemFormDialog.tsx`, the "enter manually" fallback + Edit): name, color/type/rarity (card), category (item), price AUD, purchase price, qty, notes, photo URL. **Condition is not asked when adding** — it only appears when editing an existing entry.

## Taxonomies (validated server-side as Literals → 422 on bad values)
- Colors: `red, white, blue, green, purple`
- Types: `unit, pilot, ex base, ex resource, resource, command, base, unit token`
- Rarities: `C, C+, C++, U, U+, R, R+, LR, LR+, LR++, P, P+, LKC+, LKU+, LKR+, SP, LK` (UC/UC+ removed)
- Item categories: `starter deck, accessories, premium bandai, other` (the product list's categories minus booster pack). Older values are mapped on read in `normalise_doc`: playmat/sleeves/deck box/binder → accessories, booster box/model kit → other.

## Data model — Mongo collection `items` (mirror TS interface in `frontend/src/lib/types.ts`)
`id` (uuid4 str), `kind`, `name`, `color?`, `card_type?`, `rarity?`, `category?`, `price` (AUD float, per unit), `purchase_price?` (AUD, per unit), `image_url?`, `card_id?`/`card_no?`/`set_code?`/`set_name?` (card database link), `product_id?` (product database link), `edition?` (e.g. Regular Version / Special Edition), `part?` (e.g. Playmat), `resource_cards` (list of RP card numbers), `alt_art_cards` (alt-art / EX token print ids), `sleeve_designs` (picked sleeve designs), `card_quantities` (copies per picked card/design), `card_prices` (optional per-copy prices, same keys), `part_prices` (optional price per physical part), `bundle_items` (list of `BundleEntry`: name, product_id, category, kind (`card` for a single card), code, image_url, detail, quantity, price, purchase_price, card_quantities, card_prices, parts, part_prices), `quantity`, `condition?`, `notes?`, `status`, `buyer_name?`, `deal_date?`, `sale_price?` (AUD, per unit), `created_at` (aware UTC), `sold_at?`.
Indexes in `backend/lib/db.py` (id unique, status+created_at, buyer_name, deal_date).

## API (all on api_router, prefix `/api`)
- `GET /items` → list (created_at desc); `POST /items` (201); `PUT /items/{id}` (edit; preserves sale record); `PATCH /items/{id}/status` (lifecycle; sold requires buyer+date; for_sale clears deal); `DELETE /items/{id}` (204); `GET /today` (server-anchored today; set `APP_TZ=Australia/Sydney` in `backend/.env`, otherwise it defaults to UTC); `GET /` (health check).

## Key flows
Add (UI) → appears in All Items → Mark Pending/Sold (deal dialog: buyer, date, price) → sold rows leave active tabs, land in the Sold tab with "Sold to X · date · price" → Restore (clears deal) or Delete.
